# Proposal: Student Performance PDF Report

**Change ID:** `student-performance-pdf`
**Related Task:** Tarefa 15 (Generate a PDF of a student's performance and provide a downloadable link)

## Summary
Create a new capability that generates a PDF report summarizing a student's academic performance. The PDF will be produced by a Python FastAPI service hosted on Render and stored within Xano. Users will request the report via a new Xano endpoint, receive a temporary signed URL for download, and view the report within the FlutterFlow mobile app.

## Goals
- Provide a **GET** endpoint `/reports/generate` in Xano that triggers PDF generation for the authenticated user.
- The FastAPI service will be called via a **POST** request to `/generate-pdf` (public Render URL) using the internal `SEARCH_API_KEY` for authentication.
- Store the generated PDF in Xano using the **Create File Resource → Create Attachment Metadata** workflow, linking the file to a `reports` table (or a fallback `pdf_reports` table if private file storage is unavailable).
- Return a **temporary signed URL** (validity per Xano defaults) that can be accessed without additional auth headers.
- Implement a protected **GET** endpoint `/reports/{report_id}/download` that validates ownership before returning the signed URL.

## PDF Content
The generated PDF will contain the following information (no invented grades or averages):
- Student name – using the actual name field(s) from the `user` table.
- List of enrolled subjects.
- Hours dedicated (only if the `hours` column exists in the subject schema).
- Total number of academic tasks.
- Count of tasks that are **completed**, **pending**, and **overdue**.
- Progress percentage calculated as `(completed tasks / total tasks) * 100`.

## Non‑Goals
- Internationalization (i18n) – the PDF will be generated only in the default language.
- Multi‑page reports – a single‑page layout is sufficient for now.
- Advanced charts or graphics – only plain tables/text will be used.
- Automatic scheduling of report generation – reports are generated on demand.
- Redesign of the FlutterFlow UI – UI integration is out of scope for this change.

## Security of Signed URL
A signed URL generated by Xano is **temporary**; anyone who possesses the link can download the PDF while the URL remains valid. Only the authenticated owner can request the generation of a signed URL via the protected endpoint; subsequent access to the URL does not require authentication.

## Assumptions & Open Questions (require confirmation in the real Xano environment)
1. **File Resource Availability** – Whether the current Xano plan supports private File Resources. If not, we will fall back to storing Base64‑encoded PDF data in a custom `pdf_reports` table. The final storage strategy remains a pending decision until verification.
2. **Attachment Metadata API** – The exact XanoScript syntax for creating attachment metadata after a file resource is created. We assume `api.request` can be used with the built‑in *Create Attachment Metadata* endpoint.
3. **Signed URL Expiry** – Confirmation of the default expiry period (e.g., 1 hour) for signed URLs.
4. **User Name Field** – The exact field(s) that contain the user's display name in the `user` table (e.g., `name` vs `first_name`/`last_name`).
5. **Report Table Schema** – Minimal required fields for the `reports` table (e.g., `owner_id`, `file_resource_id`, `created_at`). Confirmation needed before implementation.
6. **Environment Variable for Render URL** – The environment variable `PDF_API_URL` will hold the public URL of the FastAPI service (`https://<your-app>.onrender.com/generate-pdf`). The variable must be defined in Xano.

## Acceptance Criteria
- **[ ]** Xano endpoint `POST /reports/generate` exists, validates authentication, and forwards the request payload to the FastAPI service.
- **[ ]** FastAPI service returns a PDF binary (simulated in tests).
- **[ ]** PDF is stored via File Resource and linked to a record in `reports` (or fallback table).
- **[ ]** The response from `POST /reports/generate` includes a signed URL (`url`) that is usable without additional auth.
- **[ ]** `GET /reports/{report_id}/download` validates that `$auth.id` matches the report’s owner before returning the signed URL.
- **[ ]** If private file storage is unavailable, the fallback `pdf_reports` table stores the Base64‑encoded PDF and provides a download endpoint that decodes and streams the PDF.
- **[ ]** All new endpoints enforce proper error handling (e.g., 401 for unauthenticated, 404 for missing report, 400 for invalid request parameters).

## Risks
- Dependency on Xano’s file storage capabilities; lack of support may require a more complex fallback implementation.
- Signed URL expiration may affect downstream UI if not handled correctly.
- Incorrect assumptions about user name fields could produce incomplete PDFs.
